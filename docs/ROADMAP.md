# 竞争力路线图

> 本文是对 `docs/RESEARCH.md` §4（2026-10 厂商调研）的落地：把"不能落伍"翻译成
> **做哪些、先做哪个、做到什么算数、以及刻意不做哪些**。
>
> 每一条 P0 都已实现并带验收测试；P1/P2 是方向与验收标准，尚未动手。判断依据
> 一律来自调研文档的原文，而不是"行业大概如此"的印象。

## 0. 一个先要做的决定：不与 Harness 竞争

厂商调研 §2.1 划出的分界线是本版战略判断的起点：

- **Runtime（执行底座）**：隔离沙箱、会话状态、跨会话记忆、权限审批、凭据隔离、
  调度、追踪。**已经商品化**，是"买来的能力"。
- **Harness（agent 循环）**：谁决定下一步、子 agent 编排、工具编排、模型路由、
  eval。**这才是差异化所在，也是厂商护城河**。

**结论：本项目不建 Harness。** 理由不是"做不了"，而是做了会被夹在两头：向上不如
Anthropic/OpenAI 的托管 agent 平台，向下失去"可自托管、数据不出机房"这个唯一能让
客户选一个独立运行时的理由。**把"执行底座"这一层做完整、做到可核对，就是竞争力。**

因此下文 P0/P1 全部落在 Runtime 七能力（§2.3）上，P2 之外的 Harness 能力（循环、
子 agent、模型路由、eval）明确**不做**，写在这里是为了防止将来用"行业都做了"来反悔。

## 2. P0 —— 已实现（本版交付）

优先级逻辑：P0 是**"客户在选型表上第一眼就能淘汰你"**的三件事——没有计量、
没有公开性能数字、exec 重试会重复执行。

### P0-1 ✅ 用量计量 API

- **端点**：`GET /v1/metering`（租户 Key 见本租户；admin 用 `?tenant=` 或看全舰队）。
- **计量单位**（与调研 §3.3/§3.5 对齐）：
  - `sandbox_seconds` → 会话小时（÷3600）；
  - `cpu_millicore_seconds` → vCPU 小时（÷1000÷3600）；
  - `memory_mib_seconds` → GiB 小时（÷1024÷3600）。
- **语义**：资源秒是**采样积分**（采样器对"并发分配 × 墙钟时间"积分），不是
  请求 × 固定费率——沙箱挂一小时没有 API 流量也能被正确计量。CPU 只在可调度状态
  累计，**内存在任何非终态都累计**（暂停也占内存），即调研 §3.5 "I/O 不计 CPU 但
  内存照计"。
- **持久性**：每租户一条 `Usage` 记录进 WAL，按 `meter.every`（默认 30s）刷新；
  崩溃至多丢一个采样区间。exec 计数走请求路径的**内存增量**，与资源秒同频落盘，
  忙碌租户不会为每个 exec 付一次 fsync。读接口永远返回"已落盘 + 未落盘尾"。
- **验收**：`internal/service/meter_test.go`、`internal/store/usage_test.go`（跨
  重启 + 压实不丢）、`tests/metering_test.go`（端点 + 租户隔离 + admin 全舰队）。

### P0-2 ✅ 冷启动/吞吐基准目标

- **可复现**：`make bench` → `tests/bench_test.go`，产出 `docs/bench-summary.json`。
- **测什么**：冷启动到 `/readyz`、exec p50/p99、建沙箱 p50/p99、80 并发建沙箱。
- **方法论**（继承 `tests/commercial_test.go`）：**只测量、不对绝对毫秒数设硬断言**
  ——绝对预算是机器的属性，会在一台忙的笔记本上失败然后被静音。可依赖的是形状。
- **参考数字**（`make bench`，2026-10-11，macOS / Docker 29.5.2，随机器负载浮动，
  非承诺）：冷启动 ~0.7–8s（被隔离自检这个 I/O 密集步骤主导）、exec p50 ~24–40ms、
  建沙箱 p50 ~176–188ms、80 并发建沙箱 ~4–9s 全部准入。
- **口径说明**：竞品宣称的 25ms/90ms/150ms 是厂商口径；本项目的数字是
  `make bench` 一键复现的实测，冷启动区间被诚实地写成一个范围而不是一个最好值。

### P0-3 ✅ exec 幂等键

- **契约**（对齐 Stripe 幂等键，调研 §5.1）：请求带可选 `idempotency_key`；首次执行
  并记住结果；后续同键重试返回缓存结果且 `replayed: true`，**不再执行**；同键并发
  重试**单飞**成一次执行；同键配**不同参数**是客户端 bug，返回 409 而非静默返回旧结果。
- **作用域**：键按（租户, 沙箱, 幂等键）隔离，跨沙箱/跨租户不串味。
- **边界（诚实声明）**：缓存是内存 + 大小上限 + TTL（10 分钟）。幂等键恢复的故障
  是"响应在传输中丢失"，几秒内重发；把最大 8 MiB 的 exec 输出写进 WAL 会把一次重试
  模式变成 fsync 放大器。daemon 重启清缓存，沙箱本身由 reconciler 存活——重启后的
  重试是一次新执行。
- **验收**：`internal/service/idempotency_test.go`（重放/单飞/参数冲突/键校验/有界）、
  `tests/idempotency_test.go`（HTTP 层 + 跨沙箱隔离）。

## 3. P1 —— 方向与验收标准（未实现）

P1 是"**从'能用'到'能在严肃买方面前站得住'**"的能力。按依赖排序。

### P1-1 凭据保险库 + 占位符注入

调研 §3.1：Anthropic 的做法是"密钥值不过控制面，只注入占位符，运行时从 vault 取回"。
本项目的对应缺陷：密钥只存哈希（好），但**没有给 exec/env 提供"引用凭据而不明文传递"**
的机制——调用方要么把明文写进请求，要么不用。

- **目标形态**：`POST /v1/tenants/{id}/secrets` 存值（只存 hash/密文，回显一次）；
  沙箱 `spec.env` 或 exec `env` 里写 `"$SECRET:<name>"` 占位符，控制面在注入前替换，
  **值不落审计、不落 WAL 明文**。
- **验收**：明文凭据不出现于 `GET /v1/events`、WAL 帧、access log；占位符在沙箱内
  被替换为真值；吊销后新沙箱拿不到。

### P1-2 OTel GenAI 语义追踪导出

调研 §2.3 把"追踪"列为 Runtime 七能力之一。现状只有审计事件（谁、何时、什么动作）
与 Prometheus 指标，**没有一条跨 exec/工具调用的 trace 能回答"这次 agent 会话走了
哪条路、每一步花了多久"**。

- **目标形态**：每个 exec 生成一个 span（tenant/sandbox/argv0/duration/status），
  导出 OTLP。**零依赖约束**（`go.mod` 只有两行）意味着**手写 OTLP-over-HTTP/gRPC 的
  导出端**，不引 `go.opentelemetry.io` 客户端——这是一个刻意的取舍，写明在验收里。
- **验收**：配置一个 OTLP 端点后，一次 exec 能被 Jaeger/Tempo 看到带租户标签的 span；
  不配端点时零开销。

### P1-3 检查点原语（checkpoint primitive）

调研 §5.2 的问题"`kill -9` 之后谁负责"目前由 reconciler 回答（状态从后端重推导），
但**没有给 agent 一个"把当前状态固化为可回滚点"的显式 API**。快照是环境复用，不是
执行检查点。

- **目标形态**：`POST /v1/sandboxes/{id}/checkpoints`（命名 + 可选恢复点），对齐现有
  快照语义但面向"执行进度"而非"环境"。
- **验收**：检查点创建后，删除再恢复能回到检查点时刻的文件系统状态。

### P1-4 显式多租户形态：Silo / Pool / Bridge

调研 §3.5/§4 反复出现的三形态。本项目现在是**单机多租户（Pool 的退化形态）**。
这是刻意的（`RESEARCH.md` §3 与 `POSITIONING.md` §2 都写了"单机"），但调研让
"每个客户一个独立部署（Silo）"成为一个必须**说清楚**而不是**默认没有**的选项。

- **目标形态**：文档 + 部署配方把三形态写清——Silo（每客户一个实例）、Pool（共享
  实例、租户隔离，现状）、Bridge（自托管控制面 + 云后端）。**代码上**：Silo 只需
  部署文档，不需要新代码；Pool 是现状；Bridge 明确不做（见 §0）。
- **验收**：一份 `docs/DEPLOYMENT.md` 的"多租户形态"小节，客户能对着它选型。

## 4. P2 —— 方向（未实现，无验收标准）

- **跨会话记忆**（调研 §2.3）：让沙箱销毁后仍能按租户留存文件/状态。依赖 P1-3
  检查点与 P1-1 凭据注入先落地，否则"记忆"会先变成"凭据泄露面"。
- **调度**：多节点放置。单机做扎实之前不做；`RESEARCH.md` §3 已列为 v1 边界。

---

## 5. 刻意不做（防止将来反悔）

- **Harness / agent 循环 / 子 agent 编排**（§0 已论证）。
- **模型路由与 eval**：这是 Harness 的护城河，不是 Runtime 的能力。
- **GPU 沙箱**：隔离与计量的复杂度都不在容器档的能力范围内。
